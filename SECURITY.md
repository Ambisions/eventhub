# Security Policy

## Current status

EventHub does not yet have a formal public release tag. The `main` branch is the active development branch, and security fixes are currently evaluated only for the code on `main`.

This policy does not promise a stable API, an LTS branch, a patch schedule, production-grade security support, or a response-time SLA.

## Reporting a vulnerability

EventHub plans to use GitHub Private Vulnerability Reporting after the public GitHub repository is created. It is not enabled now, and a private security reporting channel is currently unavailable.

Do not disclose sensitive vulnerability details, credentials, secrets, exploit instructions, or private logs in a public issue, pull request, or discussion. Until a private channel is activated and verified, retain those details privately and check this policy again after repository publication.

This file will be updated only after GitHub Private Vulnerability Reporting has actually been enabled and the repository's **Report a vulnerability** entry has been verified. The current text does not claim that private reporting already works.

## Scope and expectations

Reports will be evaluated against the current `main` branch. There is no released `v1.0`, supported-version matrix, guaranteed remediation timeline, or security response SLA.

Please do not include real tokens, passwords, personal data, or production infrastructure details in any public reproduction. Use synthetic data when documenting a non-sensitive security hardening change.
